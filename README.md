# Black Myth: Wukong Benchmark — Automator

Консольный инструмент (C# / .NET 8, Windows), который локально и автоматически:

- применяет подобранные настройки к Black Myth: Wukong Benchmark Tool (Steam AppID 2435770);
- запускает бенчмарк дважды — CPU-тест и GPU-тест;
- дожидается завершения каждого прохода;
- собирает результаты и характеристики ПК в единый отчёт (консоль + TXT + JSON).

Полный сценарий занимает ~8 минут и не требует участия человека после запуска.

## Как это работает

```text
bmw-bench run
├─ 1. Обнаружение окружения: Steam (реестр) → библиотеки (libraryfolders.vdf)
│      → установка (appmanifest_2435770.acf) → exe → папка проекта ({GAME_DIR})
├─ 2. Характеристики ПК (WMI: CPU, GPU+VRAM, RAM, ОС, экран)
├─ 3. templates/: бэкап GameUserSettings.ini + генерация профилей CPU/GPU (один раз)
├─ 4. CPU-тест: подмена INI → запуск → автостарт (ЛКМ → «Тест быстродействия» →
│      «Подтвердить», OCR+клик) → пробег ~2:30 → OCR экрана результатов → закрытие окна
├─ 5. Пауза 15 с
├─ 6. GPU-тест: то же с GPU-профилем
├─ 7. Возврат оригинального INI (гарантированно — в finally)
└─ 8. Отчёт: benchmark-report.txt / .json + скриншоты + CSV PresentMon
```

## Откуда берутся результаты

Ключевая особенность тулзы: **результаты в файл не сохраняются** — финальный экран (Average/Max/Min FPS) является единственным официальным выводом (проверено Process Monitor'ом: за прогон нет записи файлов с результатами; все публичные результаты — скриншоты). Поэтому сбор идёт по трём независимым каналам:

| Канал | Что даёт | Комментарий |
|---|---|---|
| OCR финального экрана (Windows.Media.Ocr) | Average/Max/Min FPS — официальные цифры тулзы | экран детектится дёшево (кадровый дифф → статика) + таймингом (`ResultsStartAfterSec=145` при пробеге 2:30) |
| PresentMon (ETW) | Average/Max/1% Low/0.1% Low FPS, число кадров | независимая перекрёстная проверка; требует прав администратора; захват обрезается точно по моменту «Подтвердить» |
| Файловый дифф `{GAME_DIR}\Saved` | UE-логи, обновление LastCPUBenchmarkResult/LastGPUBenchmarkResult в INI и пр. | страховочный канал |

В отчёте все каналы приводятся рядом; первичным считается экран тулзы.

## Схема настроек (templates/)

Единственная точка настройки тулзы — файл:

```text
{GAME_DIR}\Saved\Config\Windows\GameUserSettings.ini
```

где:

```text
{GAME_DIR} = <Steam-библиотека>\steamapps\common\Black Myth Wukong Benchmark Tool\b1
```

`{GAME_DIR}` определяется автоматически от расположения exe (`...\b1\Binaries\Win64\b1.exe` → `...\b1`).

При первом запуске создаётся папка `templates/`:

```text
templates/
├── GameUserSettings.original.ini   ← бэкап оригинала (создаётся один раз)
├── GameUserSettings.CPU.ini        ← копия оригинала + ключи CPU-профиля
└── GameUserSettings.GPU.ini        ← копия оригинала + ключи GPU-профиля
```

Дальше — только операции с файлами:

1. бэкап/профили есть → пропустить; нет → создать;
2. перед каждым прогоном: `GameUserSettings.<ПРОФИЛЬ>.ini` → `GameUserSettings.ini`;
3. после всех прогонов: `GameUserSettings.original.ini` → `GameUserSettings.ini` (в `finally` — вернётся даже при падении).

Правка INI при генерации профиля: замена только существующих ключей (поиск по всему файлу); ключи, которых нет, дописываются в `[/Script/GSGameSettings.GSGameUserSettings]` с предупреждением — по умолчанию все ключи профилей существуют, append не срабатывает.

Формат хранения: настройки живут в двух слоях — UI-слой тулзы (строка `UISettingData=(...)`) и движковый слой (`[ScalabilityGroups]`, cvar'ы). Инструмент меняет движковый слой (`sg.*`) — его движок читает при старте независимо от UI.

## Обоснование настроек профилей

### CPU-тест

Нагрузка на процессор, минимальное влияние видеокарты:

- `sg.ResolutionQuality=50` — рендер в половинном разрешении: GPU-затраты на кадр минимальны;
- все группы качества `sg.*=0` (минимум), `r.RayTracing.EnableInGame=False`;
- `FrameRateLimit=0`, `bUseVSync=False`, `bUseDynamicResolution=False` — ничего не ограничивает частоту кадров;
- итого: GPU почти простаивает, средний FPS упирается в CPU (game thread, draw calls, стриминг) — классическая схема CPU-замера.

### GPU-тест

Максимальная нагрузка на видеокарту:

- `sg.ResolutionQuality=100` — нативный рендер, без апскейла и динамического разрешения;
- все группы качества `sg.*=3` (Epic — максимум стандартной шкалы UE; уровень 4/Cinematic можно проверить экспериментом: если тулза не сбрасывает — оставить 4);
- `FrameRateLimit=0`, vsync off — GPU работает без простоев;
- разрешение экрана сознательно не трогается — рычаг нагрузки: масштаб рендера + качество.

Разрешение, `monitorID` и прочие «личные» ключи берутся из вашего же бэкапа: профили содержат только целевые изменения.

## Автостарт теста

Стартовая последовательность (фактический UI тулзы, автоматизирована через OCR + клики по координатам распознанных строк):

1. клик ЛКМ по вступительному экрану;
2. клик по пункту «Тест быстродействия»;
3. клик по «Подтвердить».

Fallback при недоступном OCR — `AutoPressEnter`. Отсчёт длительности пробега (2:30) и обрезка захвата PresentMon начинаются от момента подтверждения.

## Требования

- Windows 11 (24H2), .NET 10 SDK;
- Steam + установленный Benchmark Tool, запущенный вручную хотя бы один раз (создаются INI и соглашение о приватности);
- PresentMon → `tools/PresentMon.exe` ([releases](https://github.com/GameTechDev/PresentMon/releases));
- языковой пакет Windows с компонентом «Оптическое распознавание символов» (Параметры → Время и язык → Язык и регион); проверка: `dotnet run -- ocr`;
- терминал от администратора (ETW-захват PresentMon);

## Запуск

```bash
git clone https://github.com/elizoorg/VKTEST.git
cd VKTEST

# положить PresentMon.exe в tools/
dotnet run --project VKTEST
```

## Команды

| Команда | Назначение |
|---|---|
| `run` (по умолчанию) | полный сценарий: CPU-тест → пауза → GPU-тест → отчёт |
| `settings cpu\|gpu` | применить файл профиля к GameUserSettings.ini без прогона (для визуальной проверки) |
| `restore` | вернуть оригинальный GameUserSettings.ini из бэкапа |
| `hw` | вывести характеристики ПК |
| `inspect` | калибровка: запускает тулзу, ждёт закрытия и показывает, какие файлы/ключи реестра она изменила |
| `ocr` | проверка OCR-движка и списка доступных языковых пакетов |
| `--config <путь>` | альтернативный путь к config.json |

## Отчёт

`benchmark-report.txt` / `benchmark-report.json` содержат:

- характеристики ПК: CPU (модель, ядра/потоки, частота), GPU (модель, драйвер, VRAM), RAM (объём, частота, число модулей), ОС, разрешение экрана;
- по каждому тесту: описание профиля, длительность, способ завершения, скриншот;
- результаты: метрики с экрана тулзы (OCR), независимые метрики PresentMon (avg/max/1% low/0.1% low), файлы с метриками (если появились);
- применённые настройки: путь к файлу-профилю и полный список ключей.

Пример вывода (сокращённо, числа условные):

```text
════════ CPU-тест ════════

  Источник настроек: templates/GameUserSettings.CPU.ini

  ── Результаты бенчмарка (OCR) ──
    Average FPS (screen)          187
    Max FPS (screen)              264
    Min FPS (screen)              121

  ── Независимый замер кадров (PresentMon, ETW) ──
    Average FPS                   185.4
    1% Low FPS                    96.2

  Настройки профиля CPU:
    INI sg.ResolutionQuality = 50
    INI sg.ShadowQuality     = 0
    ...
```

## Конфигурация (config.json)

Создаётся автоматически при первом запуске. Основные секции:

| Секция | Что задаёт |
|---|---|
| Launch | режим запуска (Steam/Executable), имена процессов, таймауты, IntroClick (клик по вступительному экрану), AutoPressEnter |
| Ocr | слова для поиска пунктов меню (MenuWords, ConfirmWords, ExcludeWords), тайминги (ResultsStartAfterSec=145 — чуть меньше пробега 2:30) |
| Settings | кандидаты пути INI (плейсхолдер {GAME_DIR}), секция append, ветки реестра |
| Results | наблюдаемые папки файлового диффа ({GAME_DIR}\Saved), глубина обхода |
| PresentMon | путь к exe, обрезка хвоста захвата (голова обрезается по моменту «Подтвердить») |
| Profiles.CPU/GPU | словари Ini-ключей каждого профиля и описание |

Плейсхолдеры путей: `{GAME_DIR}` (папка UE-проекта `...\b1`) и переменные среды (`%LOCALAPPDATA%`).

## Ограничения

- автостарт рассчитан на русскую локализацию меню (слова настраиваются в `config.json`);
- сцена и тайминги привязаны к текущей версии Benchmark Tool;
- один основной монитор, окно тулзы не должно быть перекрыто;
- `sg.*=4` (Cinematic) для GPU-профиля — экспериментально (см. [«Обоснование настроек профилей»](#обоснование-настроек-профилей));
- `templates/` создаётся автоматически при первом запуске.
